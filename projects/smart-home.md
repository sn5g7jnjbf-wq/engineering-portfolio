# 行動に寄り添うスマートホーム環境

## 概要

照明をスマートフォンから操作できるだけではなく、自分の位置や行動に合わせて、必要な機器が自然に動く環境を目指して構築しています。

きっかけは、親から電気を消すように言われることや、鍵を忘れることでした。最初はスマートフォンやAlexaから照明を操作するだけでしたが、人感センサー付き電球、Aqara FP2、Apple Home、Homebridge、Home Assistantへと段階的に広げてきました。

| 項目 | 内容 |
| --- | --- |
| 課題 | 照明などを毎回スマートフォンや音声で操作する必要がある |
| 方針 | 人の位置、時間帯、滞在時間を使って自動化する |
| 構成 | Aqara FP2 / Apple Home / Homebridge / Home Assistant |
| 結果 | センサー連動の照明制御と、Home Assistant端末のバックライト完全消灯を確認 |
| 未確認 | slot Bで消灯できる技術的理由、Stream Deckの具体的な連携方式 |

> **スクリーンショット:** Home Assistantの接続先や機器名を隠した公開用画像を、確認後に追加予定です。

## 目指したこと

一般的なスマートホームは、スマートフォンや音声で家電を遠隔操作できます。しかし、そのたびにアプリを開いたり、声を出したりする必要があります。

私が目指したのは、操作方法を増やすことではなく、操作する必要そのものを減らすことです。ベッドやデスクにいることをセンサーで判断し、生活の流れを止めずに照明などが動く環境を考えました。

## 実際に構築した自動化

- 夜間、ベッドに一定時間いると照明を消す
- デスクにいることを検知するとモニターライトを点灯する
- Apple Homeを利用して照明などを自動制御する
- Stream Deckからスマートホーム機器を操作する

「検知したらすぐ動く」だけでは誤動作につながるため、場所、時間帯、滞在時間を組み合わせることを意識しました。

## 構成の変化

### Alexa・Apple Home

照明の手動・音声操作から始め、Apple Homeのオートメーションを利用するようになりました。

### Homebridge

Matterに対応していない機器などもApple Homeで扱うため、Raspberry PiへHomebridgeを導入しました。このRaspberry Pi環境は現在稼働していません。

### Home Assistant

現在は、中古のWindowsタブレットへHome Assistant OSを導入し、スマートホーム機器を管理しています。

24時間給電する機器では、バッテリーの劣化や膨張が問題になる可能性があります。そのため、あえてバッテリー非搭載の機種を選びました。Home Assistant OSの導入自体はAIを使わずに行いました。

## バックライト問題への対応

### 発生した問題

Home Assistant OSを導入したタブレットでは、画面を黒くしてもバックライトが点灯したままになりました。24時間稼働では、無駄な発光と消費電力が続きます。

### Codexを利用した解決

Codexを利用して設定や起動方法を調査・変更し、slot Bから起動する構成でバックライトを完全に消灯できることを確認しました。

変更時には、問題が起きた場合に戻せるよう、元の環境があるslot Aを上書きせず残すよう自分から指示しました。その後、slot Aから元の環境を起動できることも確認しました。

### 自分の判断とAIの支援

| 自分で判断・確認したこと | Codexの支援を受けたこと |
| --- | --- |
| バックライトを完全に消すという目標 | 設定・起動方法の調査 |
| slot Aを復旧用として残す | 変更に必要な手順とコマンド |
| slot Bで消灯できることを実機確認 | ログや状態の確認方法 |
| slot Aから戻せることを確認 | 状況に応じた切り分け |

slot Bで消灯できる技術的な理由は、まだ確認できていません。推測を事実のように説明せず、現時点では「どの変更で、どの結果を確認したか」までを記録しています。

## 学んだこと

- スマートホームでは、操作できることより、生活の流れに自然に組み込めることが重要
- 24時間稼働では、ソフトウェアだけでなく発熱、消費電力、バッテリーも考える必要がある
- システムを変更するときは、成功手順と同時に復旧方法を確保する
- AIの提案を実行する前に、残す環境と変更する環境を自分で判断する
