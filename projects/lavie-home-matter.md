# LAVIE Home Matter

> 通学、授業、予定、天気、家電操作を、固定設置したAndroidタブレットへまとめる生活ダッシュボード。

## 概要

大学の授業開始時刻が曜日や日によって異なるため、出発前に確認する情報を一か所へまとめたいと考え、LAVIE Tab E向けのAndroidアプリを制作しています。

機能と画面構成は自分で考え、コードの実装は主にCodexを利用しました。APKを実機へインストールし、表示や操作を確認しながら、必要な機能の追加、UIの修正、軽量化を繰り返しています。

## 作ろうと考えた理由

通学時には、授業、バス、電車、徒歩、乗り換え、天気などを別々に確認する必要があります。そこで、使っていないAndroidタブレットを自宅へ固定し、出発前に必要な情報を短時間で確認できる画面を作ろうと考えました。

スマートフォンの代わりとなる小さなアプリではなく、常に同じ場所にあり、生活の情報をまとめて表示する専用端末を目指しています。

## 8つの画面

最新版`0.8.0-matter`のソースで、次の画面を確認しました。

| 画面 | 役割 |
| --- | --- |
| ダッシュボード | 時計、通学、天気、家電などの概要 |
| 時計 | 大きな時刻表示、タイマー・アラーム |
| 予定 | iCalendarから取得した予定 |
| 授業 | 曜日・時限別の時間割 |
| 交通 | バス・地下鉄の直近便と一日ダイヤ |
| 天気 | 今日、時間別、週間の予報 |
| 家電 | Matterなどのスマートホーム連携 |
| 設定 | 移動時間、表示、明るさなどの変更 |

ダッシュボードの項目をタップすると、対応する詳細画面へ移動できます。

## 主な機能

### 到着予定時刻の計算

現在時刻、バスと地下鉄の時刻表、徒歩時間、乗り換え時間を使い、乗車可能な便の組み合わせから大学への到着予定時刻を計算します。

```text
現在時刻
  ↓ バス停までの徒歩時間
乗車できるバス
  ↓ バス到着＋乗り換え時間
乗車できる地下鉄
  ↓ 所要時間＋駅からの徒歩時間
大学への到着予定時刻
```

授業開始時刻から出発時刻を自動提案する機能と、帰宅経路を検索する機能はありません。

### 交通情報

- 名古屋市営バスと地下鉄の時刻表を表示
- 直近の便と発車までの時間を表示
- バスでは終点到着予定時刻も表示
- 一日ダイヤを平日／土曜・日曜・祝日で切り替え
- 日本の祝日、振替休日、国民の休日、春分・秋分を端末内で判定

交通データは、確認できたソースでは`DefaultData.kt`へ組み込まれています。公開版では自宅を推測できる経路をサンプルデータへ置き換える予定です。

### 授業の時間割

曜日と時限ごとに、授業名と教室をアプリ上で追加、変更、削除できます。

`TimetableRepository`がデータをJSONへ変換し、Androidの`SharedPreferences`へ保存します。アプリを終了しても、端末内に時間割が残ります。

### カレンダー

`CalendarRepository`がGoogle Calendar、iCloud、OutlookなどのiCalendar（ICS）購読URLを取得・解析し、今後の予定を表示します。

処理はソース上で確認できていますが、実際のアカウントを使った接続確認状況は、公開前に再確認します。

### 天気

Open-Meteoから今日、時間別、週間の予報を取得します。取得に失敗した場合は、端末内へ保存した直前のキャッシュを利用します。

### スマートホーム

Matter、Home Assistant、Homebridge、Aqaraの複数方式を試作しました。Matter版ではQRコード、ペアリングコード、近くの機器探索を実装しています。

画面と処理は存在しますが、MatterとHome Assistantは実際の機器との接続成功を確認できていません。ポートフォリオでは、完成済みの機能としては扱いません。

### 固定端末向けの表示

- 1920×1200の横画面向けレイアウト
- ステータスバーとナビゲーションバーを隠す全画面表示
- 画面の常時点灯
- 照度センサーによる明るさと暗色表示の切り替え
- 画面スワイプによる移動
- 文字サイズなどの設定

## 技術構成

| 項目 | 内容 |
| --- | --- |
| 対象端末 | LAVIE Tab E TE710/KAW系 / Android 10 |
| 言語 | Kotlin |
| UI | Jetpack Compose 1.6.1 / Material 3 |
| 状態管理 | `MainViewModel`とCompose state |
| 非同期処理 | Kotlin Coroutines |
| 設定保存 | Android `SharedPreferences` |
| 授業データ | JSONとして`SharedPreferences`へ保存 |
| カレンダー | iCalendar（ICS）の取得・解析 |
| 天気 | Open-Meteo＋端末内キャッシュ |
| Android設定 | minSdk 28 / compileSdk 34 |
| 配布 | 署名済みAPKをPCから直接インストール |

```text
Jetpack Compose UI
        │
        ▼
MainViewModel
        ├── TimetableRepository ── 授業時間割の保存
        ├── CalendarRepository ─── iCalendar予定の取得
        ├── WeatherRepository ──── 天気取得とキャッシュ
        ├── Smart-home repositories
        └── DefaultData / JourneyCalculator
              ├── 交通時刻表
              └── 到着予定時刻の計算
```

## 自分とCodexの役割分担

| 自分で行ったこと | 主にCodexが行ったこと |
| --- | --- |
| アプリの目的と利用場面を決める | Kotlin／Composeコードの実装 |
| 必要な機能と画面構成を考える | 画面部品とデータ処理の作成 |
| 段階的に機能追加と修正を指示する | ビルドエラーや実行時エラーの修正 |
| APKを実機へ入れて動作を確認する | APKのビルド・署名手順の整備 |

独力でプログラミングしたと誤解されないよう、実装をCodexへ任せたことを明記しています。一方で、何を作るか、実生活でどう使うか、何を改善するかは自分で考え、実機で検証しました。

## 学んだこと

- 欲しい機能を曖昧なまま伝えるのではなく、表示内容や操作を具体的に言葉にすること
- 実機で使うと、PC上では気づかなかった文字サイズ、余白、操作性の問題が見つかること
- 外部サービスとつながる画面があるだけでは、接続成功とは言えないこと
- コード、APK、端末上のバージョンを整理しないと、どれが最新版か分からなくなること
- AIへ任せた範囲を正直に説明し、自分が判断・確認したことと分けること
